## 1. Context and Problem Statement

ADR-0001 integrated the enterprise network capture and alert planning specifications into the LexLean 1.2 Wireshark rewrite, establishing a formal architecture of fourteen kernel-verified modules:
1. Five core Wireshark modules (`Wireshark.Capture`, `Wireshark.PcapNg`, `Wireshark.Dissector`, `Wireshark.Filter`, `Wireshark.Invariants`).
2. Five enterprise capture/alert modules (`Enterprise.CapturePipeline`, `Enterprise.Normalization`, `Enterprise.FileServerThreats`, `Enterprise.AlertOperations`, `Enterprise.Invariants`).
3. Three PRISM foundation facet modules (`Foundation.Arch`, `Foundation.Qual`, `Foundation.Sec`).
4. One unified top-level integration module (`Main`).

Verification currently relies on a manual shell script (`verify.sh`) executing sequential CLI calls (`lexlean fmt`, `lexlean lock`, `lexlean check`, `lexlean verify`, `lake build`, `prismpm check`, `prismpm build`). While functionally correct for manual developer invocations, this presents several production vulnerabilities:
- **Zero Automated Audit Artifacts**: No structured human-readable Markdown or machine-readable JSON reports are generated or synchronized with source changes.
- **Documentation Drift**: Verification findings, Lean attestation hashes, and PrismPM release IDs must be manually recorded in `README.md`, introducing human error risk.
- **Lack of Granular Suite Diagnostics**: A failure in one stage obscures downstream subsystem health; execution times and command traces are unmetered.
- **Absence of Commit and Remote Gates**: No local git pre-commit hook or GitHub Actions CI/CD pipeline exists to prevent regressions from landing on `main`.

Following the proven pattern established in `kuramoto-prism` (`run_tests.py`, `run-tests.sh`, `reports/`, `.githooks/pre-commit`, `install-hooks.sh`, and `.github/workflows/verify-test.yml`), this decision record establishes an automated, fail-closed verification harness tailored to the Wireshark and enterprise network capture model.

---

## 2. Decision Drivers

1. **Single Source of Truth**: One authoritative Python test runner (`run_tests.py`) encapsulates all suite commands, pass/fail predicates, and report formatting.
2. **Fail-Closed Verification**: Any regression in formatting, lockfile parity, AST type checking, kernel attestation, or release packaging terminates execution with a non-zero exit code.
3. **Synchronized Human-Readable Reporting**: Every execution produces a clean, self-contained Markdown report (`TEST_REPORT_LATEST.md`) alongside a schema-governed JSON ledger (`test_report_latest.json`).
4. **Semantic Drift Detection via Fingerprinting**: Reports compute a canonical SHA-256 fingerprint over invariant findings (excluding volatile timestamps and execution durations), allowing CI to detect real documentation drift without spurious failures.
5. **Domain-Specific Verification Matrix**: Rather than copying numerical Kuramoto oscillator benchmarks, Suite TS-09 evaluates seven dedicated domain audit sub-suites (`SUITE-W1` through `SUITE-R1`) targeting Wireshark invariants and enterprise threat detection thresholds.
6. **Reproducible Tooling & Digest Verification**: Tool manifests (`tools.lock`) and pinned bootstrap scripts guarantee identical CLI versions and cryptographic integrity locally and across CI runners.
7. **Additive and Non-Destructive**: The formal Lean 4 sources, `.lex.tex` modules, closed lexicons, and ADR-0001 thresholds remain completely untouched.

## 3. Decision Outcome

We implement an end-to-end automated test harness, reporting infrastructure, and CI/CD pipeline for `/run/media/multiplic/AGI/prismagi/mount/SUBSYSTEMS/production`:

```text
production/
├── run_tests.py                         Authoritative suite runner + report generator
├── run-tests.sh                         Shell wrapper with PATH normalization
├── verify.sh                            Thin delegate to ./run-tests.sh --quiet
├── tools.lock                           Pinned toolchain versions and cryptographic SHA-256 digests
├── scripts/install-tools.sh             Digest-checked CI bootstrap script
├── reports/
│   ├── TEST_REPORT_LATEST.md            Stable human-readable latest report (tracked)
│   ├── test_report_latest.json          Stable machine-readable latest report (tracked)
│   ├── TEST_REPORT_<UTC>.md             Immutable timestamped report (CI artifact)
│   ├── test_report_<UTC>.json           Immutable timestamped report (CI artifact)
│   └── logs/                            Per-suite raw stdout/stderr logs (git-ignored)
├── .githooks/pre-commit                 Fail-closed local pre-commit hook
├── install-hooks.sh                     Git repository initializer and hook installer
└── .github/workflows/verify-test.yml    Automated CI verification and report publishing pipeline
```

### 3.2 Adapted Domain Invariant Sub-Suites (`TS-09`)

Replacing the numerical oscillator stress benchmarks of `kuramoto-prism`, `TS-09` executes seven structural and semantic property audits:

1. **`SUITE-W1` (Wireshark Core Protocol Model)**:
   - Evaluates snaplen bounds, link types, and magic numbers (`PCAP: 0xa1b2c3d4`, `PCAPNG: 0x0a0d0d0a`).
   - Validates 32-bit boundary alignment for pcapng blocks (SHB, IDB, EPB).
   - Verifies dissector tree hierarchy, recursion depth limit ($\le 32$), and display filter AST evaluation soundness.
2. **`SUITE-E1` (Enterprise Capture Pipeline & Schema Normalization)**:
   - Validates 4-tier pipeline ordering: Acquisition $\to$ Sensors $\to$ Transport $\to$ Storage.
   - Enforces VXLAN/GENEVE outer tunnel stripping while preserving inner payload integrity.
   - Confirms OCSF canonical identity: $\mathrm{type\_uid} = \mathrm{class\_uid} \times 100 + \mathrm{activity\_id}$.
3. **`SUITE-E2` (File-Server Threat Detection Rules & Thresholds)**:
   - Rule 1: Administrative share payload upload (`ADMIN$`, `C$`, `IPC$`) with executable extension (`.exe`, `.dll`, `.ps1`, `.bat`).
   - Rule 2: Rapid directory traversal ($\ge 15$ distinct target shares within $10.0\,\text{s}$).
   - Rule 3: Mass ransomware overwrite/rename bursts ($\ge 50$ operations within $60.0\,\text{s}$).
   - Rule 4: Data exfiltration burst volume ($\ge 500$ events within $300.0\,\text{s}$).
4. **`SUITE-E3` (Alert Operations, Threat Scoring & SOAR Response)**:
   - Baseline suppression logic for scheduled administrative backups and IT management tasks.
   - Contextual threat score accumulation with critical escalation threshold ($\ge 85.0$).
   - Correlation to host agent GUID and automated SOAR containment dispatch.
5. **`SUITE-X1` (Joint Integration Soundness)**:
   - Verifies `Enterprise.Invariants.enterprise_pipeline_sound` and `Main` integration/rejection theorems linking packet capture limits to enterprise alert generation.
6. **`SUITE-F1` (PRISM Foundation Facets)**:
   - Audits ISO-42010 Architecture (`Foundation.Arch`), ISO-25010 Quality (`Foundation.Qual`), and ISO-27005 Security (`Foundation.Sec`) formal representations.
7. **`SUITE-R1` (Report Integrity & Fingerprint Consistency)**:
   - Validates JSON parseability, Markdown field alignment, byte identity between timestamped and latest report pairs, and fingerprint equality against committed baseline.

### 3.3 Report Contract

- **Human-Readable Report (`reports/TEST_REPORT_LATEST.md`)**:
  - Executive summary with pass/fail badges, timestamp, and toolchain versions.
  - Complete cryptographic attestation block (Semantic ID, Source Hash, Lean Kernel Attestation, PrismPM Release Hash).
  - 9-Suite execution matrix with per-suite targets, status, and durations.
  - 14-Module formal verification breakdown with certified theorem descriptions.
  - Invariant audit matrix for `SUITE-W1` through `SUITE-R1`.
  - Attestation artifact inventory and diagnostic logs.
- **Machine-Readable Ledger (`reports/test_report_latest.json`)**:
  - Top-level schema: `lexlean-test-report/1`.
  - Canonical JSON projection computing the deterministic `fingerprint` (excluding volatile timestamps and execution times).
- **Retention Policy**:
  - `reports/TEST_REPORT_LATEST.md` and `reports/test_report_latest.json` are committed to git.
  - Immutable timestamped copies (`TEST_REPORT_<UTC>.md`) and suite logs (`reports/logs/`) are archived in CI and git-ignored.

### 3.4 Local Pre-Commit and Remote CI/CD Pipelines

- **Local Pre-Commit Gate (`.githooks/pre-commit`)**:
  - Executed automatically on every `git commit`.
  - Runs `./run-tests.sh --hook`.
  - On failure: halts commit, displays failing suite diagnostics and raw log paths.
  - On success: explicitly stages only `reports/TEST_REPORT_LATEST.md` and `reports/test_report_latest.json` before finalizing the commit.
- **Hook Installer (`install-hooks.sh`)**:
  - Automatically initializes `git init -b main` if `.git` does not yet exist.
  - Configures `core.hooksPath = .githooks` and installs `.git/hooks/pre-commit` fallback.
- **GitHub Actions CI/CD (`.github/workflows/verify-test.yml`)**:
  - Triggers on pull requests and pushes to `main` with path filters covering sources, configs, and tooling.
  - Executes isolated workflow: sets up Python 3.11, installs Lean 4 via `leanprover/lean4-action`, bootstraps LexLean and PrismPM using `tools.lock` with SHA-256 verification.
  - Runs `./run-tests.sh --ci`.
  - Emits `reports/TEST_REPORT_LATEST.md` directly into `$GITHUB_STEP_SUMMARY`.
  - Archives `reports/` as CI artifact `wireshark-lexlean-reports`.
  - On `main` merge: triggers `publish-reports` CD job for immutable release publishing.

## 5. Acceptance Criteria

Execution is verified and accepted when all of the following conditions hold:

1. `python3 run_tests.py` reports 9/9 suites `PASS` with exit code 0.
2. `reports/TEST_REPORT_LATEST.md` and `reports/test_report_latest.json` are generated and strictly synchronized.
3. Two consecutive unchanged runs produce identical `semantic_hash`, `attestation`, `published_hash`, theorem counts, and canonical `fingerprint`.
4. `verify.sh` delegates to `./run-tests.sh --quiet` and returns 0.
5. Local pre-commit hook halts commits on injected failures and auto-stages only the two latest reports on success.
6. `install-hooks.sh` initializes `main` branch when executed without an existing `.git` directory.
7. `scripts/install-tools.sh` verifies cryptographic SHA-256 digests from `tools.lock` without placeholder steps.
8. CI workflow uploads test artifacts and publishes `TEST_REPORT_LATEST.md` to `$GITHUB_STEP_SUMMARY`.
9. Zero changes are made to `.lex.tex` formal modules, lexicons, or ADR-0001 thresholds.

## 6. Consequences

### Positive
- **Guaranteed Formal Rigor**: Mathematical and structural invariants cannot silently regress.
- **Continuous Audit Readiness**: Every commit and pull request contains an up-to-date, human-readable verification ledger.
- **Complete Parity**: Brings `/run/media/multiplic/AGI/prismagi/mount/SUBSYSTEMS/production` into identical operational standards with `kuramoto-prism`, `o3de-prism`, and `skip-logic`.
- **Early Regression Detection**: Local pre-commit hooks catch type errors and broken proofs before network push.

### Negative & Mitigations
- **Commit Latency**: Running Lean 4 kernel verification on 14 modules adds ~20-30 seconds to commits.  
  *Mitigation*: Retain strict fail-closed policy locally and in CI; optimize execution via Python sub-process streaming and Lake caching; avoid any "skip" shortcuts.
- **Lockfile & Fingerprint Maintenance**: Legitimate formal changes require updating the baseline.  
  *Mitigation*: The test runner explicitly flags baseline drift in stdout, guiding the engineer to review and record changes in a deliberate commit.
